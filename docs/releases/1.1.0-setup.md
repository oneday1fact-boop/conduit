# CONDUIT 1.1.0 candidate (version code 3)

Pro price: **US$2.99, one time**, product `conduit_pro_lifetime`. Localized prices come from Google Play. This grants available past Daily puzzles and a calendar with completion/in-progress states. Daily and the existing three Practice puzzles remain free. Pro does not remove or add ads: rewarded Hint ads remain optional, with one hint per puzzle. Archive wins do not change Daily streaks.

## Implemented

- Three-mode navigation, compact phone layout, Pro upgrade screen and monthly archive calendar.
- Email/password Firebase sign-in, account creation, password reset and email verification before purchase.
- Per-account cloud progress, local guest migration, separate local account saves, restoration across devices and completion-preserving merges. Guest data survives sign-out. Only puzzle progress and Daily completion history sync; sound/theme/haptics stay device preferences.
- Native Play Billing 9.1.0 purchase/restore bridge. Pending/canceled purchases never unlock Pro. A hashed Firebase UID binds the purchase to its CONDUIT account.
- Firebase callable functions verify purchases through the Google Play Developer API, acknowledge them, and write server-only Pro entitlements. Refund notification and periodic rechecks revoke invalid entitlements. Clients cannot write entitlements or purchase tokens.
- In-app account/cloud-progress deletion with recent sign-in required. Purchase deletion support limitations are disclosed before confirmation.
- Existing package ID and signing configuration retained. Production build script retains real AdMob app/rewarded IDs and child/under-age consent flags; debug builds retain test ads.

## Setup needed before internal release

1. Connect the **existing** CONDUIT Firebase project (project ID and public web-app config; no private key in the app). Put that public config into `www/firebase-config.js`. Enable Firebase email/password Auth and Firestore. Enable email enumeration protection, configure verification/reset templates, password policy and appropriate authorized domains. Do not create a replacement project.
2. Review existing Firebase resources and rules before deploying the included `firebase.json`/`firestore.rules`. These rules deny other paths; merge with any existing project rules instead of overwriting unrelated applications. Use the existing project explicitly (`firebase ... --project EXISTING_PROJECT_ID`).
3. Cloud Functions requires project billing. Use an application-default service identity; grant only the required Google Play purchase verification/acknowledgment permissions for `com.oneday1fact.conduit`. Enable the Android Publisher API. No service-account JSON belongs in GitHub or the APK.
4. Complete Play merchant/payments setup if still outstanding. Create one non-consumable one-time product `conduit_pro_lifetime` with exactly one permanent buy purchase option at US$2.99 and appropriate local prices. No subscription or rental offers. Restrict initial validation to license testers.
5. Deploy Auth/Firestore/functions only after verifying the selected project and reviewing policy changes. Configure Play RTDN topic `conduit-play-billing`, the Google Play publisher IAM permission, and notification delivery. Schedule rechecks are a fallback. Test refunds and revocation.
6. Review account creation against the app's existing all-ages/Families audience before enabling it. Update privacy policy, Data Safety (email/user IDs, cloud gameplay progress, purchase history and service-provider processing), App access/reviewer instructions and the Play account-deletion URL. Current published disclosures describe the older no-account app; they must not be reused unchanged. No sensitive declarations have been submitted by this change.
7. Run `npm ci`, `node scripts/build-cloud.cjs`, `npx cap sync android`; install backend locked dependencies with `npm ci --prefix functions`. Use emulator/staging tests before connecting production users.
8. End-to-end test two physical Play-installed devices: old guest upgrade, sign-in, first purchase, canceled and pending payments, completed pending payment, restore, sign-out/account switch, offline edits/reconnect, refund, account deletion and old save migration. Ensure consent/no-fill/rewarded Hint ads work. Confirm no credentials or purchase tokens appear in logs.
9. Build on the machine holding the **original** `~/.conduit-signing/key.properties` and upload keystore using `bash build-android-production.sh`. Validate version code 3 is still greater than every Play upload, verify upload certificate, then prepare internal release notes. Do not create a new signing key.
10. Show the final AAB, policy changes, price/product setup and release notes to the owner before submitting any release or changing availability.

## Known limits / honest status

Firebase config is intentionally null until the existing project is identified. Free play works; account/purchase controls clearly report unavailable. No actual payment, cloud sync, deployed rules/functions, or new signed release has been verified yet. Auth uses email/password; existing third-party sign-in providers have not been discovered or replaced. Pro currently requires an online entitlement check after app launch; no permanent editable local unlock flag is stored.

Account deletion removes Firebase Auth and cloud progress. It does not refund a Google Play purchase. A minimal non-reversible purchase-token hash is retained to guard against reuse; moving a deleted account's purchase requires support. Review this retention disclosure and support process before launch. Add abuse protection/App Check and monitor billing/Firestore costs before public availability.
