# CONDUIT 1.1.0 — Spark/free-tier activation

Owner decision: keep the existing Firebase project `conduit-22893` on **Spark**. Pro remains **US$2.99 once**. No Firebase/Google Cloud billing account is to be linked and no paid Cloudflare plan is to be selected.

## Implementation

Firebase Google Auth and Firestore store user progress and server-written Pro entitlements. Purchase verification, acknowledgment, restore, account deletion and periodic refund checks run in a separate **Cloudflare Workers Free** service (`billing-worker/`). The public game/puzzle Worker is unchanged. Purchase tokens remain in server-only Firestore paths; no additional D1/database product is needed.

Firebase Cloud Functions code and deployment configuration have been removed. The app calls the HTTPS verification Worker with its Firebase ID token. The Worker verifies the JWT signature, issuer and project audience before accessing private data. Only Google's Play Developer API can confirm payment. Pending, canceled, refunded, other-account and replayed tokens do not grant Pro.

Free plans have quotas. If capacity or an upstream quota is exhausted, verification fails closed and the user can retry; no automatic paid-plan upgrade is configured. This is not a promise of unlimited free usage. Confirm the actual Cloudflare account is on Workers Free before deployment. Official references:
- https://firebase.google.com/docs/projects/billing/firebase-pricing-plans
- https://developers.cloudflare.com/workers/platform/pricing/
- https://developers.cloudflare.com/workers/platform/limits/

## Concrete activation steps

1. Sign in to the existing Google/Firebase/Play and Cloudflare accounts. No new Firebase project or replacement Android app registration.
2. Publish the reviewed `firestore.rules` in `conduit-22893`. They retain the existing schema-1 paths and validation and add owner-only `progressV2` and read-only-to-client entitlements. Existing registered signing fingerprints must remain intact.
3. Create or select a dedicated Google service identity for this app only. Proposed Firebase runtime permissions: `datastore.entities.get`, `datastore.entities.list`, `datastore.entities.create`, `datastore.entities.update`, `datastore.entities.delete`, and `firebaseauth.users.delete`, scoped to this project. Grant only this app's required Play purchase verification/acknowledgment/order permissions. Do not grant Owner/Editor or account-wide Play administration.
4. **Explicit owner approval is required before granting those permissions or storing a service-account credential in Cloudflare.** Put its JSON only in the separate Worker's encrypted `GOOGLE_SERVICE_ACCOUNT_JSON` secret. Never put it in chat, GitHub, app assets, build artifacts or the public game Worker. Enable the relevant APIs only if this can be done without linking billing; stop if the console requires a paid-plan change.
5. In `billing-worker`, run `npm ci`, `npm test`, and `npm run build`. Deploy its built module with `wrangler.jsonc`, initially `SERVICE_ENABLED=false`. Configure hourly maintenance. Verify project identity, origins, API permissions, quotas, and a license-test purchase before enabling the service. Use the actual verified deployment URL in `www/firebase-config.js` as `CONDUIT_BILLING_API_URL`; do not guess a URL.
6. Create the Play non-consumable one-time product `conduit_pro_lifetime`, one permanent buy option at US$2.99, with localized prices from Play. Merchant setup is still required if incomplete. No subscription/rental. Complete actual canceled/pending/paid/restore/refund tests using Play license testers. The periodic batch checks up to eight older purchases each hour; each app launch/restore also checks its purchase directly. Real-time refund notifications are not yet integrated in this free backend.
7. Review the proposed privacy/Data Safety/account-deletion changes before publishing them. Google and Cloudflare now process authentication/purchase verification traffic. Preserve existing Families/child-directed ad flags and review account handling for the all-ages audience.
8. Verify two-device login/progress/restore, offline recovery, account isolation and account deletion. Only then set `CONDUIT_CLOUD_SERVICES_READY=true`. Until then free play works and account/purchase controls explain that services are being prepared.
9. Use the original upload key on its existing signing machine to build version 1.1.0/code 3 with `bash build-android-production.sh`. Release tooling uses the live rewarded AdMob unit; debug builds use test ads. Recheck Play's highest uploaded version code and signing certificate before upload.
10. Upload a signed AAB to an internal-testing **draft** only. Do not submit rollout/production changes or sensitive declarations without showing the owner the final proposed result.

## Validation and remaining limits

App/puzzle/release tests, Worker business/API rejection tests, Worker bundling, Android compile and Firestore security-emulator tests are the required checks. Mocked receipts verify backend policy but do not substitute for live Google Play license tests. Server credentials, live backend deployment, Play product activation, policy publication and signing are separate activation gates.

Account deletion removes the app's known progress/settings/private document collections and Firebase Auth account. A temporary account-ID guard blocks stale tokens from recreating data; maintenance removes expired guards. A non-reversible purchase-token hash remains as a reuse guard after deletion; moving a purchase after account deletion requires support. No purchase is automatically refunded by deleting an account. Review these retention/support details before launch.
